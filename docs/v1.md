# EthioNLP Documentation (Version 1)

EthioNLP is an open-source Amharic natural language processing toolkit designed for Ethiopian languages.

## Features

- Tokenization
- Transliteration
- Spell checking
- Smart spell ranking
- Word frequency scoring

## Implemented Modules

### 1. Tokenizer

Splits Amharic text into individual tokens.

Example input:

```text
ሰላም እንዴት ነህ
```

Example output:

```text
["ሰላም", "እንዴት", "ነህ"]
```

Current API endpoint:

```text
POST /analyze
```

Response fields include tokens, word count, sentence count, character count, unique words, and word frequency.

### 2. Transliteration

Converts Ethiopic script into Latin script.

Modes:

- Academic
- Friendly

Examples:

```text
ሀ -> hä
ሐ -> ḥä
ጸ -> ṣä
```

```text
ሀ -> ha
ሐ -> ha
ጸ -> tse
```

Example input:

```text
ሰላም
```

Academic output:

```text
sälam
```

Friendly output:

```text
selam
```

Current API endpoint:

```text
POST /transliterate
```

Supported request modes:

- academic
- friendly

### 3. Spell Checker V1

Uses Levenshtein distance.

Minimum edits include insertion, deletion, and substitution.

Example input:

```text
እሄዳሉ
```

Suggestion:

```text
እሄዳለሁ
```

Current API endpoint:

```text
POST /spellcheck/v1
```

Response shape:

```json
{
  "results": [
    {
      "input": "እሄዳሉ",
      "suggestions": [
        {
          "word": "እሄዳለሁ",
          "distance": 1
        }
      ]
    }
  ]
}
```

### 4. Spell Checker V2

Uses weighted ranking.

Components:

- Edit distance
- Prefix similarity
- Length penalty

Score formula:

```text
score = distance + length_penalty - prefix_bonus
```

Lower score means a better suggestion.

Current API endpoint:

```text
POST /spellcheck/v2
```

### 5. Word Frequency Ranking

Common words receive higher priority.

Example:

```text
WORD_FREQUENCY = {
    "ሰላም": 2500,
    "ቤት": 1200
}
```

Final score:

```text
final_score = distance - prefix_bonus - frequency_bonus
```

## API Endpoints

### Tokenize

```text
POST /analyze
```

Request:

```json
{ "text": "ሰላም እንዴት ነህ" }
```

Response includes the token list and summary statistics.

### Transliterate

```text
POST /transliterate
```

Request:

```json
{ "text": "ሰላም", "mode": "academic" }
```

The `mode` field defaults to `friendly`.

Response suggestions are ranked by weighted score, where lower is better.

## Algorithms Used

- Tokenization: text segmentation
- Transliteration: script conversion
- Levenshtein distance: spelling similarity
- Prefix similarity: candidate ranking
- Frequency weighting: language probability

## Implementation Notes

- Tokenization is currently whitespace-based after removing a small punctuation set.
- Transliteration uses a SERA-style mapping for academic output and a simple academic-to-friendly conversion for friendly output.
- Spell checker v1 ranks by Levenshtein distance only.
- Spell checker v2 adds normalization and weighted scoring.

## Current Limitations

- Small vocabulary dataset
- Manually assigned frequencies
- No contextual understanding
- No machine learning model
- No corpus-based statistics
- Tokenizer and spell-check endpoints are still simple rule-based implementations
- Transliteration is character-mapping based, so it does not yet handle every linguistic edge case
